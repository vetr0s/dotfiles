Dotfiles repository audit

2026-09-08dotfiles @ 076b062Repository audit

The repository is usable and its main entry points load today. Its deployment design is clear. One design choice puts personal Emacs state at risk. Several editor and macOS paths contain verified behavior bugs. Protect Emacs state first. Then fix Python environment isolation and the C formatting cache before changing anything unrelated.

Scope

The audit covered all 66 tracked files. It reviewed deployment, shell startup, editor configuration, terminal configuration, macOS integration, Linux guidance, helper scripts, manifests, notes, file modes, and font metadata. It excluded ignored Emacs packages and generated caches from code review. It also excluded the binary contents of the five fonts and the two vendored minimal-emacs.d entry files. Their metadata, ownership, pinning, and integration remained in scope.

The audit did not inspect third-party plugin internals. It checked each declared dependency, lock entry, bootstrap path, and local integration point.

What is solid

Keep these parts

The shared and platform manifests form a clear deployment model. Existing targets receive unique backups. A failed link restores the displaced target. Correct links remain unchanged on later runs. The root setup wrapper is small and useful.

  • Emacs loads modules in an explicit order at .emacs.d/post-init.el:27-39. The large C and Odin modules remain cohesive.
  • Neovim pins every declared plugin at nvim/lazy-lock.json:2-14. The full configuration starts under Neovim 0.12.5. OLS attaches to an Odin buffer.
  • Vim starts without vim-plug because the plugin block is guarded at .vimrc:175-186.
  • The launch agent keeps Emacs in the foreground at macos/emacs/dev.nathantebbs.emacs.plist:9-13. Launchd supervises the real daemon.
  • No tracked token, password, private key, or API key was found. GitHub authentication remains delegated to gh at gitconfig:4.
  • All five tracked fonts expose the expected family and style metadata. The installed copies match the committed bytes.

Verification

Both documented platform dry runs completed. Every current target resolved to the expected repository source.
Shell
All tracked shell scripts and shell configuration passed bash -n. ShellCheck was unavailable.
Editors
Emacs loaded 123 modules. Neovim started and attached OLS. Vim started with the committed configuration.
Formats
JSON, plist, Git config, Kitty config, and AeroSpace TOML passed available parsers. AeroSpace runtime inspection was unavailable because its service was not running.
C formatting
Clang-format 23.1.0 returned different C and C++ widths from one multi-document style. The directory-only cache cannot represent that result.
Dependencies
Homebrew reports that clang-format needs installation or update on this machine. This is host drift because the Brewfile already declares it.
Repository
git fsck and git diff --check passed. No tracked secrets were found.

Recommended order of work

  • Move Emacs runtime state out of the checkout without losing the current 131 MB state tree.
  • Remove the current directory from PATH. Fix Python environment isolation and Flymake selection.
  • Correct the clang-format cache key and invalidation. Add focused ERT fixtures before changing the cache.
  • Fix the Odin ftplugin cleanup and align Odin root detection across editors.
  • Repair the tmux reload path, Karabiner rule, missing tmux dependency, font installer, and font modes.
  • Make the Neovim bootstrap and Emacsclient app replacement atomic. Fix the macOS readiness and diagnostic paths.
  • Add a repository verification command for deployment, syntax, config parsing, and focused editor tests.
  • Document Linux requirements, the Neovim minimum, and the chosen dependency pinning policy.
